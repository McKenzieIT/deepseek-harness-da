## Resolution

Resolved 2026-09-04 (this session). `ui-present-table` wired to consume `ctx.results` (the T9 cache) via a slot inject face; the TSV scan demoted to cache-miss fallback; fresh-vs-folded invalidation + retry=refetch implemented. **`ui-present-decomposition` not touched** — per [R10](R10-decomposition-table-metric-identity.md), decomposition is pure argsRaw free-text with no `result_id`, so it has nothing to fetch (the args explicitly scoped T10 to `ui-present-table` only).

**Implementation** (decisions beyond R5/T9's contract recorded in the Agent Note [`.agents/notes/implemented/architecture/2026-09-04-client-present-table-fetchresult-wiring.md`](../../../../.agents/notes/implemented/architecture/2026-09-04-client-present-table-fetchresult-wiring.md)):

1. **Inject face** (`index.ts`): `inject = ['slots', 'sessions', 'locale']`; the `tool.call.toolview` register call gains `inject: (sessionId) => ({ fetchResult, invalidateResult })`, reached through `sessions.scope(sessionId)?.get('results')` (a local `TableResultsFace` cast, mirroring result-cache's own `ctx.get('connection') as ConnectionHandle`). `fetchResult` always returns a Promise — a missing service degrades to `Promise.resolve(undefined)` (not-found → TSV fallback), never a non-Promise that would throw on `.then`.
2. **`useFetchResult` hook** (`TableCard.tsx`): component-internal (no external subscription — only `useState`/`useRef`/`useEffect`), holds the inject-face callbacks in refs so the effect's identity deps stay `[resultId, freshSeq, retryNonce]` (a new function instance per render cannot re-trigger a fetch). fresh-vs-folded via `freshSeq` (the bound query_data's `seq`, now retained on `BoundQuery`): invalidate only when `freshSeq` ADVANCES past `lastInvalidatedSeq` (a new same-turn `query_data` re-ran) → invalidate + refetch (R5); fold/expand (same `freshSeq`) does not re-run the effect → the cached entry in state is reused (G1: fold/expand preserves data, no re-RPC). `retry` bumps `retryNonce` → refetch (failures not cached → re-RPC).
3. **`decideTable` fallback ladder**: fetchResult success → entry rows (`resultEntryToTableData` coerces `unknown[][]` to the string pipeline; SQL from `entry.metadata?.sql ?? bound.sql`); not-found (undefined) → TSV fallback if a bound `query_data` exists, else expired+retry (G1 D2); reject (any error) → expired+retry (no TSV fallback on error — the spec scopes the fallback to no-face/not-found); no `fetchResult` face → TSV fallback, no retry. `ExpiredCard` gained an optional retry button (new `retry` locale key).
4. **No cross-package import** (AGENTS.md export discipline #3): `TableCard.tsx`/`index.ts` import nothing from `@deepseek-ai/dsh-client-result-cache` (neither value nor type) — a local `FetchResultEntry` mirror (structurally identical) + `TableResultsFace` cast. Errors are duck-typed (the UI treats every rejection uniformly → expired+retry; no `instanceof ResultFetchError` + no value import).
5. **`toTableData` shared** by the entry + TSV paths (the `args.columns` override + `MAX_DISPLAY_ROWS` cap live once, exercised by the TSV tests).

**Invalidate-on-first-observation per instance is the v1 safe approximation** (init `lastInvalidatedSeq` to `-1`): a new card instance may observe a `query_data` whose seq is newer than what a previous instance cached (the cache key is `(sid, rid)`, not seq), so invalidating on first observation is the only way to guarantee the latest snapshot without R5's deferred generation-token. The cost is a re-RPC when a remount sees the same seq (the cache was fresh); accepted (the gen-token, deferred per R5, would close it). The code-review subagent flagged this as a cache-defeat across remounts; the reviewer's fix (skip the first-mount invalidate) would risk stale data, so NOT applied — see the Agent Note.
