# G4 — query sidecar 控制信道 + 可靠性：P1（da 自持 Client，additive）vs P2（改 mcp-client core 复用 reconnect）

**Type**: grilling
**Phase**: 2
**Status**: Resolved (2026-08-20)
**Blocks**: [P4b query-maxcompute 生产硬化](P4b-query-maxcompute-hardening.md)（控制信道 + 崩溃恢复形态 = 硬化前置判断，已定；P4b 已开 unblocked）

**Question**: R6 已定 (b) per-call `set_credentials` + **P1**（da 自持 raw SDK `Client`+stdio transport 连 query sidecar，不用 mcp-client plugin，sidecar 工具非 model-facing per A1-split → 控制信道缺口消解、additive-only）为**推荐**。但 adversarial 复核（`../../research/r6-cred-hot-reload-review.md`）确认推荐成立的同时 surface 了 **HOLE-B**：P1 自持 raw Client = da **自担 sidecar 生命周期含崩溃恢复**，而 mcp-client `connection.ts` 已有成熟 reconnect（`RECONNECT_DEFAULTS` frozen、`scheduleReconnect` 指数退避、`maxAttempts` 耗尽注销、`onclose`→`generationDown`→`scheduleReconnect` 自动驱动、`GENERATION_CLOSE_TIMEOUT_MS` 防重叠子进程）——P1 **放弃复用**这套。这是 **additive-only standing principle 不能独裁的可靠性判断**（原则定默认走 P1，但 P1 的可靠性代价是否可接受需人裁）。grilling 一问一答定调：

1. **da 的 sidecar 崩溃恢复策略**（HOLE-B，P1 内部形态选择）：(i) mini reconnect loop（da 重写指数退避，+行数+债）；(ii) lazy on-next-call re-spawn（`ctx.query.execute` 检测死 Client → re-spawn+re-connect，简单但崩溃后首条 query 付重启延迟）；(iii) 不重连（崩溃即停服，等 HMR/人工）。决定 P1 真实行数与可靠性形态。
2. **是否值得为复用 mcp-client 成熟 reconnect 而做 P2 小 core 改**（真正的 P1-vs-P2 判断轴）：P2 = mcp-client `ConnectionHandle` 加 `callTool(rawName, args)` + allowlist/hidden-registration 特性（让 da 复用 plugin 的 Client+reconnect 生命周期，sidecar 工具不全量 model-facing）。若团队判「query sidecar 长驻、per-scope ODPS 连接需保活、崩溃需快速恢复」→ 复用成熟 reconnect 值得做小 core 改（P2 转正，P1 退兜底）；若判「sidecar 崩溃罕见、lazy 重连可接受（query 本就用户发起、非连续）」→ P1 的 additive 优势压过可靠性债。
3. **`initialize` 握手义务**（HOLE-A）+ **在途查询 per-scope 原子性**（HOLE-C）的实现定调：da 须 `await client.connect(transport)`（自动跑 `initialize`+`notifications/initialized`+协议版本校验，connect 失败 `close()`+抛）；sidecar 在 `set_credentials` 时对在途 query 是 drain（等完）还是 cancel（强杀）——「原子」一词过强（drop 连接缓存不必然 abort 在途 ODPS 作业，reverse-bi `invalidate_credential` `credentials.py:192` 同张力）。附带 HOLE-D（SDK `Cancelled`/`Progress` notification 是否 wire 到 `ctx.query.execute` 的 timeout/cancel）。

**Context**: R6（`../../research/r6-cred-hot-reload.md` + `R6-cred-hot-reload.md`，resolved 2026-08-19）定 (b)+P1；adversarial 复核（`../../research/r6-cred-hot-reload-review.md`）7 claim 全 VERIFIED、(b)+P1 成立（`Protocol.request()` `shared/protocol.js:611` 是纯 JSON-RPC send、非 `tools/list`-gated 实证 P1 技术支点；`enforceStrictCapabilities` 可选默认 falsy、mcp-client `new Client` `connection.ts:238` 未设；`assertCapabilityForMethod('tools/call')` 只查 server `tools` capability 不查 tool-name-in-`tools/list`），但 surface HOLE-A（initialize 握手）/B（reconnect 可靠性债，最重）/C（在途原子性）/D（notification）。P4 A1-split（sidecar = da-internal dumb executor，会话门留 `tool-query`，sidecar 工具非 model-facing——P1 修复了前置研究括注「经 mcp-client」与 `syncTools` 全量 model-facing 注册的潜藏冲突）。常设原则 additive-only / intranet-security-first。reverse-bi read-only（`invalidate_credential` 双清是 (b) 的语义镜像）。

## Resolution（resolved 2026-08-20，wayfinder "work through the map" grilling session）

**P1 + (ii) lazy on-next-call re-spawn + HOLE-A 强制 connect + HOLE-C drop + HOLE-D no-op polling。** 详见 research 笔记 [`../../research/g4-sidecar-reliability.md`](../../research/g4-sidecar-reliability.md)（subagent 2026-08-20 源码深挖 §1-§8，每 claim 引 path:line）。

- **Q1 崩溃恢复 = (ii) lazy on-next-call re-spawn**：`ctx.query.execute` 检测死 Client（`client.onclose`→`dead=true` ~5 行 + `client.onerror` log ~3 行）→ `connectingPromise` 单 owner 锁防并发 double-spawn ~10 行 → re-spawn 子进程 + `await client.connect(transport)`。**在途 query 崩溃后 SDK `_onclose`（`protocol.js:248-273`）兜底 reject ConnectionClosed、不 hang**（caller/RetryGuard 处理）；崩溃后首条 query ~1.5-3.5s 延迟（spawn node ~100-300ms + initialize 握手 ~5-20ms + 首条 ODPS 连接 1-3s）；per-scope 缓存重建 = re-spawn 新进程全丢（仅崩溃时；cred 变更已走 `set_credentials` surgical 不重启 per R6 §7）。~40-70 行。query-maxcompute = Service Provider（fiber-scoped，非 mcp-client plugin 的 `apply`+`ctx.effect`）；HMR/dispose→Service stop→`client.close()`→在途 reject + sidecar kill（ODPS 孤儿作业归 OrphanReaper A1-split engine-wrapper 门，独立处理）。(i) mini reconnect loop ~120-180 行（复刻 mcp-client `connection.ts:202-290` 去 syncTools/enqueueSync）对 da 非连续 query 过建、不取；(iii) 不重连最差不取。
- **Q2 P1 vs P2 = P1（da 自持 raw SDK Client+stdio transport）**：纯 additive——新 `packages/query/query-maxcompute/` 不碰 core；da 按 raw name 程序化调全部 sidecar 工具（query 五件 `execute/attach/cancel/get_progress/estimate_cost` + 控制 `set_credentials`/`invalidate_scope`），无一进 `ctx.tools`→无 `syncTools`→无 model-facing 注册→控制信道缺口消解、`set_credentials`/`invalidate_scope` 天然非 model-callable。P2（`ConnectionHandle` 加 `callTool(rawName,args)` ~15 行 + **必须** allowlist/hidden-registration ~30-50 行 + export handle seam ~15-30 行 = ~60-100 行 core 改 3 处 `connection.ts:99`+`tools.ts:143,181`+`index.ts`）违 additive-only/碰上游升级路径、且倒置（比 P1 还重）；P1 是 P4 原型（`run.mjs:27` raw-stdio stand-in）产品化、非偏离，P2 引 `syncTools` 全量 model-facing 才是偏离。mcp-client reconnect 6 能力（指数退避/maxAttempts give-up/stability-window crash-loop 防护/`GENERATION_CLOSE_TIMEOUT_MS` 孤儿防护/`isCurrent` race-safe/`enqueueSync` 串行化）对 da 用户发起非连续 query 模式过建；仅 maxAttempts give-up + 孤儿防护两项高价值、~10 行已简化入 Q1 lazy（crash-loop 计数器）。
- **Q3 HOLE-A/C/D**：
  - **HOLE-A（initialize 握手义务）**：da 须 `await client.connect(transport)`（SDK `client/index.js:285` 自动跑 initialize+协议版本校验+`setProtocolVersion`+`notifications/initialized`；connect 失败 `:324` SDK 自动 `void this.close()`+抛）。da 仅 `try{await client.connect(transport)}catch{throw}` ~5-10 行（已计入 Q1 ~40-70）。失败处理：**初始启动 connect 失败→抛（fail-fast，Service/Provider 启动失败 surface 错误）；lazy re-spawn connect 失败→Q1 已含 crash-loop 计数器 bounded 重试**（无 hang：sidecar spawn 后崩在 initialize 响应前→`_onclose` reject initialize request `protocol.js:271`→connect 抛 ConnectionClosed→可 RetryGuard）。
  - **HOLE-C（在途 query per-scope 原子性）= drop**：`set_credentials` = 推新凭据 + 丢该 scope 连接缓存（`_CACHE.pop`+`_CONNECTIONS.pop` 镜像 reverse-bi `invalidate_credential` `credentials.py:192-206` 纯 drop、不 drain/cancel/wait）；**在途 query 持旧 ScopeConnection 跑到完、下次取新值**；弃「原子」措辞（reverse-bi `connection.py:1-30` 自述生产零执行、da 复刻=等价可信度）；cancel 留给显式用户 cancel 工具。drop 对 da 安全（同 scope 已授权、无跨 scope 泄漏、bounded；PAT 不进 spawn-env 保 intranet-security-first）——leaked-cred 轮换时在途继续用泄露凭据至完成，已接受。drain（加延迟+in-flight 计数，reverse-bi 无先例）/cancel（强杀在途，破坏性，reverse-bi 无先例）不取。
  - **HOLE-D（Cancelled/Progress notification）= no-op polling**：SDK `Protocol` 构造器（`protocol.js:27-32`）自动装 Cancelled+Progress handler，但仅 sidecar **发** notification 才触发；P4 `sidecar.mjs` 纯请求/响应零 notification（pending→attach 轮询）→ handler 不触发 = no-op 无害。**outbound cancel 经 `request()` 的 `signal` 已内建**（`protocol.js:670-714` AbortSignal→发 `notifications/cancelled`+reject），da TimeoutGuard 传 `signal` 给 `client.request()` 即可，~0 行额外接线；progress 走 `get_progress` 轮询工具。YAGNI：sidecar 若未来改 progress 推送，届时传 `onprogress` callback（`protocol.js:643`）~5-10 行。

**NEW 边界（R6 HOLE 之外，subagent 源码深挖 surface，实现期处理）**：(1) da raw Client 生命周期挂点 = Service Provider（非 plugin），HMR/dispose→`client.close()`→在途 reject+sidecar kill、ODPS 孤儿归 OrphanReaper；(2) 单例 Client 并发 double-spawn 须 `connectingPromise` 单 owner 锁；(3) stdio 背压 SDK 已内建（`send()` write false→`once('drain')`）；(4) initialize 启动竞态无 hang（spawn 后崩在 initialize 响应前→`_onclose` reject→connect 抛→lazy RetryGuard）；(5) dispose 终态复用 stdio `close()`（stdin.end→2s→SIGTERM→2s→SIGKILL，mcp-client `GENERATION_CLOSE_TIMEOUT_MS=5000`=4s+1s buffer）；(6) onclose=reject 在途+clear 状态 vs onerror=仅 callback（设 `client.onclose`→`dead=true` ~5 行 + `onerror` log ~3 行；EPIPE 极短窗口但 close event 必到无永久 hang）。

**解锁**：生产硬化 `packages/query/query-maxcompute/`（控制信道 + 崩溃恢复形态是其前置判断，已定）→ 开 **P4b** 生产硬化 prototype 票落地（`P4b-query-maxcompute-hardening.md`，unblocked）。

## Design（P1 接线骨架，P4b 实现期落实）

`packages/query/query-maxcompute/` 作 Service Provider（fiber-scoped，镜像 credentials `extends Service`），自持 raw SDK `Client`+`StdioClientTransport`（一个 sidecar 子进程）：

- **启动**：Service start → `new Client({name,version},{capabilities:{}})` + `new StdioClientTransport({command,args,env:buildChildEnv(scrubbed)})` → `try{await client.connect(transport)}catch{throw}`（HOLE-A；失败 fail-fast）。`client.onclose=()=>{this.dead=true}` + `client.onerror=(e)=>log`。
- **ensureConnected()（lazy re-spawn）**：`ctx.query.execute` 入口先 `if(this.dead||!this.client)return this.reconnect()`；`reconnect()` 用 `connectingPromise` 单 owner 锁（并发 query 共享一个 re-spawn）→ `stopSidecar()`（kill 旧子进程，复用 stdio `close()` 终态）→ `startSidecar()`+`await client.connect(transport)`→清 `dead`。crash-loop 计数器 bounded 重试（maxAttempts，超限抛）。
- **程序化调用（raw name）**：`client.request({method:'tools/call',params:{name,arguments}},RawCallToolResultSchema,{signal,timeout})` 调全部 sidecar 工具——query 五件（`execute/attach/cancel/get_progress/estimate_cost`）经 `ctx.query.execute` engine-wrapper guard chain（cost/timeout/retry/orphan，A1-split）；控制 `set_credentials`/`invalidate_scope` 经 `credentials/updated` 事件 + per-call `ctx.credentials.resolve`。无一进 `ctx.tools`（无 `syncTools`、无 model-facing 注册）。
- **outbound cancel**：TimeoutGuard 传 `AbortSignal` 给 `client.request({...,signal})`→SDK 自动发 `notifications/cancelled`+reject（`protocol.js:670-714`）。inbound Cancelled/Progress handler 留 no-op（sidecar 零 notification per P4）；progress 走 `get_progress` 轮询工具。
- **set_credentials（cred 热更）**：da per-call `ctx.credentials.resolve` 4 ref（`ODPS_ACCESS_ID/KEY/PROJECT/ENDPOINT`）→ `client.request('tools/call',{name:'set_credentials',arguments:{scope_id,creds}})` → sidecar 推新值 + 丢该 scope 连接缓存（`_CONNECTIONS.pop`，drop 镜像 reverse-bi，在途持旧跑到完）。非-cred 配置→`invalidate_scope`（sidecar 重读 scope `config.yaml`）。reconnect→崩溃兜底（lazy re-spawn）。
- **dispose**：Service stop → `await client.close()`（stdio 终态：stdin.end→2s→SIGTERM→2s→SIGKILL）→ kill sidecar 子进程；在途 query reject ConnectionClosed（caller/RetryGuard 处理）；ODPS 孤儿作业归 OrphanReaper（A1-split engine-wrapper 门）。

~40-70 行新增（HOLE-A connect ~10 + ensureConnected+connectingPromise ~30 + crash-loop ~5 + onclose/onerror ~8 + dispose ~5）。不碰 mcp-client core；mcp-client plugin 仍用于真正 model-facing 外部 MCP server。
