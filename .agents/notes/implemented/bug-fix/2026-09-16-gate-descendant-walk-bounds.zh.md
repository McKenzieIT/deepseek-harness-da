# Agent Note: 为 gate runner 的进程树遍历定界

Status: implemented

[English](2026-09-16-gate-descendant-walk-bounds.md) | 中文

## Problem

gate runner 会枚举已结束 gate 的后代进程，以便在 Windows 上终止整棵树。该遍历假定它读到的进程表 dump 是一棵树。事实并非如此：操作系统会复用 pid，因此一行可以指向一个编号已被回收、且在同一份快照里位于其自身子进程下方的「父进程」，而 `Get-CimInstance Win32_Process` 报这种行与报任何其他行一样自然。

两处细节把这个假设变成了崩溃。遍历的队列别名了它自己父索引里存放的子数组，而不是拷贝，因此往队列里追加就会改写遍历仍在读取的快照；当环回到根时，队列每轮翻倍。遍历还通过 spread into `push` 追加子进程，而 spread 每个元素占一个实参，于是队列一变宽就超出引擎的实参上限。V8 把这种实参溢出报成 `Maximum call stack size exceeded`。

结果是：gate runner 把一条测试全部通过的 lane 判成失败。一个 Windows coverage job 报 failure，而它的日志里没有任何测试失败，实际死在 gate 结束后运行的清理回调里——又因为 runner 是 fail-fast，该 lane 的其余部分再也没有跑。

## Decision

遍历现在记录每个已入队的 pid，并拒绝二次入队，因此它由行数定界，而不是靠信任快照的形状。环形 dump 现在让每个 pid 只产出一次，而不再无限增长。队列以拷贝起步，因为父索引持有的正是遍历仍在读取的活动子数组。子进程逐个追加，这条实参上限的路径被彻底移除。

该函数现在已导出。它此前没有任何直接用例覆盖，这正是「遍历无法承受的快照形状」长期未被发现的原因。

## Alternatives considered

**加大栈空间。** 该失败是实参数量溢出，不是递归深度，所以更大的栈只会挪动阈值，两处缺陷都不会消失。环形快照仍会把队列涨到内存耗尽。

**在遍历外层捕获 `RangeError`。** 那样 gate 会在进程树未被终止的情况下通过，后续 gate 于是继承了仍持有 stdio 句柄的游离进程。吞掉这个错误，恰好掩盖了遍历存在的意义所在的那种状况。

**在 Windows 上跳过后代枚举。** 以已退出的 pid 为根去终止什么也找不到，因为 Windows 从不重新指派父进程；一旦直接子进程先退出，去掉枚举就会泄漏整棵子树。

## Consequences

终止一棵 gate 进程树现在每行多一次集合成员检查。含环的快照现在产出正确的后代列表而不是抛异常，lane 的红绿判定重新与它的测试结论一致。回归用例钉住了此前会抛异常的各种形状：环回到根、不含根的环、自指父行、宽于引擎实参上限的扇出，另加一次重复遍历以证明调用方的行未被改写。
